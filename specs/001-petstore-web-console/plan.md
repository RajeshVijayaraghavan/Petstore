# Implementation Plan: Petstore Web Console

**Branch**: `001-petstore-web-console` | **Date**: 2026-03-22 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-petstore-web-console/spec.md`

## Summary

Build a Petstore Web Console — a single-page application for non-technical pet store staff to browse pets by status, manage pet CRUD operations, view inventory summaries, place and cancel orders, and administer user accounts. The front-end is a React 19 + Vite 6 SPA consuming the existing Petstore OpenAPI 3.0.4 REST API (v1.0.27) with no backend modifications required. All API types, query hooks, Zod schemas, and MSW mocks are auto-generated from the OpenAPI spec via Orval v8. The Stitch design system ("The Curated Console") provides the authoritative visual specification using Material 3 tonal palette tokens, Manrope/Inter typography, and a no-line layout philosophy.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode), React 19, Node.js 20+ (build tooling)
**Primary Dependencies**: Vite 6, React Router v7, TanStack Query v5, Zustand v5, React Hook Form v7, Zod, shadcn/ui (Radix + Tailwind CSS v4), Orval v8, react-oidc-context
**Storage**: N/A (front-end only; all persistence via Petstore REST API)
**Testing**: Vitest v3 (unit/integration) + React Testing Library (components) + Playwright (E2E) + MSW (mock handlers generated by Orval)
**Target Platform**: Desktop and tablet web browsers (Chrome, Firefox, Safari, Edge)
**Project Type**: web-app (single-page application)
**Performance Goals**: Sub-200ms loading indicator display; ~93KB gzipped JS bundle estimate; sub-2s Vite dev server startup
**Constraints**: Client-side only (no SSR, no BFF); 5 MB max image upload; client-side pagination/sorting; OAuth2 PKCE flow for auth; no `any` or `@ts-ignore`
**Scale/Scope**: ~8-10 routes, 7 screens, 5 domain entities, 19 API endpoints
